🚀 部署 / 更新

双项目：控制面（面板 + 订阅 + 探针）+ 数据面（代理入站），共用同一个 KV。

自动判断：KV 有记录则启动「更新现有部署」，没有则启动「全新部署」。
⚠ 全新部署会新建一个 KV，忽略「凭据」页 KV 选择，自动填写新参数。
⚠ 更新现有部署会复用「凭据」页 KV 选择，复用所有原参数。

域名会写进控制面的 DATA_HOST变量（订阅里的节点地址）， 该部署不自动绑定域名。部署成功后请到 Cloudflare 控制台 → Workers 和 Pages → 该 Worker →「域」标签页 → 添加自定义域名（与上方填写值一致）。
留空则节点用 *.workers.dev —— 多数网络直连不可访问，节点无法连接。

⚠ 更新部署时如果切换模式，新数据面上线后会自动删除旧的数据面 （Pages 或 Worker），旧的自定义域名会随之失效，需要重新绑一次。

部署完成后，密码会显示在日志中（面板密码在云端加密，事后无法再读取）。

🔗 链式代理（自建落地节点）

在你自己的 VPS 上装一个带口令的 SOCKS5 落地节点， 让流量走 客户端 → Worker → VPS → 目标站。 目标站看到的是你的 VPS 出口（干净），而不是 Cloudflare 的机房 IP。 



            

              · 需要本机有 ssh 客户端（Windows 10+ 自带）且已配好密钥。

              · 没有密钥也能用：点「复制命令」在终端里执行 —— 终端里 ssh 才会提示输入密码。

              · 脚本会装 sing-box、生成随机口令、起 systemd 服务，仅支持 Debian/Ubuntu/CentOS 系。

              · 跑完会打印一行 socks5://用户:口令@IP:端口，粘到面板「出站与高级」→ SOCKS5。

              优选IP流程说明
              

                整体流程（四阶段，全部基于真连接校验，不采信单纯 TCP 延迟）：

                阶段一 · TCP 握手初筛 —— 从 Cloudflare 网段按「实测可用率加权」采样候选，
                测 TCP 握手延迟，剔除完全不通的 IP；

                阶段一之二 · TLS 握手筛选 —— 用你的域名作 SNI 完成完整 TLS 握手，
                淘汰「能建 TCP 但握手极慢 / 失败」的 IP
                （这是优选 IP 导入客户端后延迟 -1 的主要根因）；

                阶段二 · 两层校验 —— 第一层 WebSocket 101 协议升级：
                排除 Enterprise 专属 IP 与 SNI 阻断；
                第二层 响应体内容校验：发 PING 验证数据面真实响应，
                拦截「握手能过但实际不可用」的假活 IP；

                阶段三 · 真实下行测速 —— 多连接 + 丢弃预热期，
                按稳态吞吐排序（单窗口峰值会虚高，不作为排序依据）；


                补充说明：

                · 最终结果按 /16 网段轮流取优，避免整批集中在一个网段、
                一段路由拥塞就全军覆没；

                · CFPilot 实例走自有探针端点测速；其它项目回落公开测速地址；

                · 勾选「跳过测速」时退化为纯延迟排序（速度列显示 —）；

                · 机房国家筛选在阶段二之后生效（机房码只有 101 响应里才有）；

                · 每次优选成功自动留底到下方「优选历史」，可多选复制、二次复测可用性；

                · 结果输出在下方，可复制到 Web 面板的「手动优选 IP」框，或点「回填面板」直接写入。

📘 功能说明

            

              CFPilot 的图形化部署与维护工具。功能与命令行版
              cfpilot deploy / cfpilot scan 一致，
              适合不接触命令行的用户。
            

            

              首次部署流程

              1. 在「凭据」页填写 Token 并保存，「当前使用」中选中账号（系统识别到暂无CFPilot实例）

              2. 切换到「部署」页，选择「自动判断」，输入面板密码（不填则随机），点击「开始部署」

			  · 运行日志显示部署成功后的相关信息，请手动保存备查


			  Web 面板

			  1. 查看运行日志或点击「查看面板凭据」获取面板地址，浏览器中打开，输入登录密码进入控制台

			  2. 「运行概览」页点击「复制订阅链接」，导入代理工具即可遨游全球网络

			  · 默认分配 30 个节点 = 优选域名 10 个 + 官方优选 IP 20 个


			  优选 IP

			  1. 在「优选」页点击自动识别，其他保持默认，点击「开始优选」，等待优选结果

			  2. 「回填面板」：自动获取临时 Token 并填入面板并保存，订阅直接生效

			  3. 「复制结果」：Web 面板打开「节点来源」，手动指定 IP 中粘贴结果，保存并应用

			  · ⚠️「回填面板」将清空原有的手动指定 IP，增选请使用「复制结果」

              · 优选 IP 稳定且短期不会失效，无需每日优选；节点测试延迟 -1 请再次测试


              升级内核

              1. 在「凭据」页「当前使用」中选中账号（系统自动识别 CFPilot 实例）

			  2. 唯一 CFPilot 实例：「部署」页点击「检查状态」，提示版本差异，点击「更新到最新内核」按钮

			  3. 多 CFPilot 实例：「凭据」页选择本次部署使用的 KV，其他同上

              · 订阅地址、面板密码、面板路径、WS 路径、UUID 均保持不变


              关于 CFPilot

              CFPilot 采用双项目部署一对实例：控制面（Web 面板）+ 数据面（流量转发），
              实测稳定无1101、无8000119，支持在触发 CF 限制时进行无损更新部署

              不建议在同一账户下部署多个 CFPilot 实例；若确有需求：创建新的 KV，选择该 KV 后部署第二对

              本项目已支持数据面 Workers 形式部署（新手建议使用默认 Pages）
            

          


          

            
🔒 安全说明

            

              API Token 与面板密码仅写入本机
              ~/.cfpilot-gui/secrets.json，不会上传到任何服务器，
              也不随安装包分发。


              工具的出境网络请求仅三类：

              · api.cloudflare.com —— 部署必需，令牌仅用于该请求的 Authorization 头

              · 你自己的域名 —— 优选阶段的 101 握手校验

              · 你主动点击的官方链接 —— 以系统浏览器打开


              不存在「把令牌发到第三方」的路径。可随时点击「删除本地账号/凭据」清除。

❓ 常见问题

            

              面板无法打开？面板路径是随机生成的，部署日志中会打印。


              优选结果全是 -1？检查域名与 WS 路径是否与客户端一致，端口是否为 443 等 TLS 端口。


              提示「版本相同已跳过」？说明线上已是最新版本，无需重新部署；确需强制更新请启用「强制重新部署」。


              部署失败？查看下方日志中的具体错误；权限问题可对照「凭据」页的权限说明。
