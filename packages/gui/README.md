# CFPilot GUI

CFPilot 的图形化部署与维护工具。功能与命令行版 `cfpilot-deploy` / `cfpilot-scanner` 相同，
适合不想碰终端的用户。

## 下载

在 [Releases](https://github.com/xmwengxing/CFPilot/releases) 页面下载：

| 文件 | 说明 |
|------|------|
| `CFPilot-<版本>-x64.exe` | 安装版：可选安装目录、创建桌面与开始菜单快捷方式 |
| `CFPilot-<版本>-portable.exe` | 便携版：免安装，双击即用 |

两个版本功能完全一致，都**不需要**预先安装 Node.js。

## 三步部署

> **数据面实现**：默认使用本项目**自研**实现（失败可诊断、支持 SOCKS5 / HTTP / HTTPS 代理池、
> DoH 优选解析、可配置反代入口）。需要切回 CFNext 原版时，在部署页的
> 「数据面实现」下拉框选 `CFNext 原版` 即可（对应 `DATAPLANE=vendor`）。

1. **Cloudflare 凭据** —— 粘贴 API Token 并保存，点「**检测账号**」，
   再点「**刷新 KV 列表**」，在下拉框里选一个命名空间
   - 带 **●** 的是本工具部署过的实例（选它 = 更新该实例，UUID 与 WS 路径不变）
   - 带 **○** 的是空命名空间或被别处占用
   - 要部署**新实例**，点「**新建 KV**」给它单独建一个
2. **一键部署** —— 点「开始部署」。日志会给出控制面与数据面的地址
3. **本地真连接优选** —— 填上一步的**数据面域名**与 WS 路径，跑一次优选，
   把结果粘贴到面板的「手动优选 IP」

> **一个 KV 命名空间只能承载一个 CFPilot 部署实例。**
> 内核在 KV 里用的键是全局平铺的（`CONFIG` / `PANEL_PATH` / `SESSION:*` …），没有实例前缀，
> 两个实例共用一个 KV 会互相覆盖 UUID、WS 路径与面板密码。
> 因此部署前会校验归属：选中的 KV 若属于另一个实例，**部署会被中止**并提示新建。
> 这是有意为之——写坏别人的线上项目比部署失败严重得多。

## ⚠️ 优选 / 部署前必须关闭代理工具

这是最容易踩的坑，也是「结果看起来正常但导入客户端全是 -1」的头号原因。

> **2026-10-23 补充**：代理工具的 **TUN 模式**除了影响优选测速，
> 还会让**部署向导写 KV 静默失败**（Node 的 `fetch` 报 `fetch failed`，
> 但同一接口用 curl 却正常 —— TUN 与 undici 的兼容性问题）。
> 后果是数据面 KV 里没有 `CONFIG` 键 → **WebSocket 路径 404，节点连不上**。
> 部署日志里出现「⚠ KV 凭据写入失败」时，先关掉 TUN 再重试。

优选测的是**本机直连某个 IP 的真实质量**。只要流量被代理接管，
测出来的就是**到代理的延迟**而不是到目标 IP 的延迟：

- Clash / Mihomo（**含 TUN 模式与系统代理**）
- v2rayN / v2rayNG
- sing-box / Nekoray
- Surge / Quantumult

**症状**：扫描不报错，但所有候选 IP 成绩趋于一致（常集中在一个小网段），
导入客户端后大量 `-1`。

**做法**：点「本地真连接优选」页的「**检测网络环境**」按钮。
工具会检查本机监听的代理端口、系统代理设置、以及 fake-ip DNS，
发现异常会在日志里明确列出。点「开始优选」时也会自动做一次同样的检查。

检测到问题**不会阻断扫描**（有些人确实需要走代理），但结果可信度需自行判断。

## 关于 WS 路径

路径**必须与目标项目实际的 WebSocket 路径完全一致**，填错一个 IP 都选不出来：

| 项目 | 常见路径 |
|------|---------|
| CFPilot / CFNext | `/vless` 或一长串 UUID |
| 部分项目 | 根路径，填 `/` |
| 不知道 | 分别试 `/` 和 `/vless`，能出结果的那个就是对的 |

校验方式是发起真实的 **TLS + WebSocket 101** 握手，只有返回 101 才算可用，
所以填错路径不会产生「假结果」，只会一个都选不出来。

## 测速支持任意项目

测速**只对已通过 101 校验的 IP 生效** —— 这是避免「速度快但导入客户端全是 -1」的关键。

工具会自动选测速方式：

- 目标有 CFPilot 探针端点（`/__edge_probe`）→ **走项目自身路径**，最忠实
- 其它项目 → 自动改用**公开测速地址**（默认 `speed.cloudflare.com`）

所以**对接第三方项目时速度不再永远是 0**，也不需要手动勾选「跳过测速」。

测速精度上做了三件事：

| 做法 | 原因 |
|------|------|
| 取**滑动窗口峰值**，丢弃前 1 秒 | TCP 慢启动会让开头严重偏低。实测同一 IP 峰值 51.7 MB/s，总平均仅 16.4 MB/s |
| 默认 **3 条并发连接** | 单条 TCP 连接受拥塞窗口限制，高延迟线路填不满带宽 |
| 测速地址**可用性预检** | 避免把「测速地址不可用」误判成「所有 IP 速度都是 0」 |

「测速连接数」建议保持 3、「测速时长」建议 5~8 秒。
「测速地址」留空即可自动选择；填了则强制使用（以 `/` 开头会被当作探针路径）。

## 更新升级

再跑一次「开始部署」即可：工具在 KV 里存了部署清单，认得自己的项目，
会沿用原有的 UUID 与 WS 路径，**客户端订阅地址不用改**。

勾选「强制重新部署」可忽略「版本相同则跳过」。

### 更新本程序

「说明」页有「检查更新」：从 GitHub Releases 查最新版本，
点「下载并安装」后会下载便携版 exe 并在替换后重启程序。

> Windows 首次运行时 SmartScreen 可能提示「已阻止无法识别的应用」，
> 点「更多信息」→「仍要运行」即可。安装版**不需要管理员权限**。

## 安全

API Token 与面板密码只写在本机 `~/.cfpilot-gui/secrets.json`：

- **不会上传**到任何服务器，也不随安装包分发
- 工具的出境网络请求只有三类：
  - `api.cloudflare.com`（部署必需，令牌仅用于该请求的 Authorization 头）
  - 你自己的域名（优选阶段的 101 握手校验）
  - 你主动点击的官方链接（用系统浏览器打开）
- 不存在「把令牌发到第三方」的路径
- 随时可点「清除本机凭据」删除

## 已知限制

- 首次部署在部分环境可能因 GPU 进程起不来而失败（远程桌面 / 虚拟机常见）。
  工具会自动用 `--disable-gpu-sandbox` 降级重启；若仍失败，请更新显卡驱动
  或关闭安全软件的「应用沙箱」功能。
- 数据面复用 CFNext 的实现，**面板里配置的 SOCKS5 / HTTP 代理池不会生效**，
  只有 `PROXYIP` 有效。

## 从源码运行

```bash
npm install
npm run build -w @cfpilot/gui
npm run start -w @cfpilot/gui
```

打包：

```bash
cd packages/gui
npm run dist
```

产物在 `packages/gui/release/`。

> 打包需要 `TEMP` 指向可写目录（NSIS 的 makensis 需要创建临时文件），
> 且 npm 的 allowScripts 策略需放行 electron-builder 的子进程安装。
