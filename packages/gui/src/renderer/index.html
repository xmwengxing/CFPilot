🗄️ KV 命名空间

一个 KV 命名空间对应且仅对应一个 CFPilot 部署实例。 内核在 KV 里用的是全局平铺的键（CONFIG / PANEL_PATH / SESSION 等），没有实例前缀， 两个实例共用一个 KV 会互相覆盖凭据与面板密码。

点「刷新 KV 列表」查看账号下有哪些命名空间。带 ● 的是本工具部署的实例， 带 ○ 的是空命名空间或他人在用。

从别的机器迁移、或 KV 列表里没显示时，可直接粘贴 ID。

选中后点「保存此选择」会记住它；不保存则每次部署都使用下面这个下拉框里的当前项。

⚡ 本地真连接优选

用你自己的域名做 TLS 握手 + WebSocket 101 + 响应体内容三层校验，只保留真正能连通且数据面在响应的 Cloudflare IP。跑完直接得到可粘贴的 IP 列表。

你的代理域名（数据面的地址）。检查更新后会自动填入。 用它做 TLS SNI 与 HTTP Host，才能测出真实可用性。
建议使用自定义域名，避免 Cloudflare 项目提供的 *.pages.dev 生产链接在部分网络被阻断—— 拿被阻断的域名测优选，结果本身就不准。 点「自动识别域名」可自动填入：有自定义域名优先填它，没有则填 pages.dev。

必须与目标项目实际的 WebSocket 路径完全一致，否则一个 IP 都选不出来。
· CFPilot / CFNext：通常是 /vless 或一长串 UUID
· 部分项目直接用根路径，那就填 /
· 不知道就分别试 / 和 /vless，能出结果的那个就是对的

按住 Ctrl / Shift 多选。只保留这些国家/地区的 Cloudflare 机房；不选则按采样数跑全量测试。
筛选只影响「已通过 101 校验」的候选。采样太小可能某些国家没有候选， 提示筛空时请调大「候选采样数」到 500~1000 再试。

建议 10~20。太多会让订阅变长且质量下降。
端口固定为 443——Cloudflare Pages 的 HTTPS 入口； 2053 等端口在部分网络环境会被中间设备阻断，故不提供选择。

建议 3000 起。阶段一要按 TLS 握手耗时筛选， 而 TLS 握手快慢和 TCP 延迟几乎无关（实测 TCP 9ms 的 IP， TLS 可能要 3.5 秒）—— 采样小了根本碰不到握手快的 IP。
第一次测新网络建议 5000~10000，确认能选出低延迟 IP 再降回来。

留空即可，工具会自动决定：
· 目标有 CFPilot 探针端点（/__edge_probe）→ 走它，最忠实
· 否则 → 用公开测速地址（默认 speed.cloudflare.com）
填了则强制用你指定的地址（需返回大文件，如 xxx/__down?bytes=104857600）。

建议 3。单条 TCP 连接受拥塞窗口限制，测不满真实带宽； 多条并发取峰值更接近实际可用速度。

建议 5~8。太短会被 TCP 慢启动拉低（前 1 秒的样本会被丢弃）。

阶段二会做两层校验（借鉴 CFData-WEB 的「链路复验」）：
· 第一层 WebSocket 101 握手 —— 排除 Enterprise 专属 IP、SNI 阻断
· 第二层 响应体内容校验 —— 发 PING 并验证数据面回 {"pong":true,...}，把「101 通但数据面不响应」的假活 IP 拦掉

测速已支持任意项目，不再需要手动跳过：
· 目标有 CFPilot 探针端点 → 走项目自身路径测速（最忠实）
· 其它项目 → 自动改用公开测速地址测速
两种方式都只对通过两层校验的 IP 测速，所以不会选出连不上的 IP。

对接非 CFPilot 项目时，第二层校验可能全部不通过 —— 此时用命令行加 --no-verify 退回纯 101 校验。

勾选「跳过测速」才会退化为纯延迟排序（速度列显示 —）。 勾选「不回填」时结果只在下方显示，复制到面板「手动优选 IP」框即可。

⚠️ 运行前请关闭所有代理工具（Clash / Mihomo / v2rayN / sing-box / Surge 等）， 包括 TUN 模式与系统代理。

优选器测的是「本机直连该 IP」的真实质量。流量一旦被代理接管， 测出来的就是到代理的延迟而不是到目标 IP 的延迟 —— 结果看起来正常，但所有 IP 成绩趋于一致，导入客户端后大量 -1。

如果必须开着代理，请把本程序加入直连/绕过名单。 点「检测网络环境」可以帮你确认当前是否处于干扰状态。

📘 这是什么

CFPilot 的图形化部署与维护工具。功能与命令行版 cfpilot-deploy / cfpilot-scanner 相同， 适合不想碰终端的用户。

三步部署
1. 在「Cloudflare 凭据」页填 Token 并保存，点「检测账号」，再点「刷新 KV 列表」
2. 在下拉框里选一个 KV（带 ● 的是已有实例，空的可以部署新实例），点「开始部署」
3. 在「本地真连接优选」页填上一步得到的数据面域名，跑一次优选，把结果粘贴到面板的「手动优选 IP」

更新升级
再跑一次「开始部署」即可：选同一个 KV，工具认得自己的项目，会沿用 UUID 与 WS 路径， 客户端订阅地址不用改。

部署多个实例
一个 KV 只能承载一个实例。要在同一账号下跑多个， 点「新建 KV」给每个实例各建一个，然后分别选对应的 KV 部署。

❓ 常见问题

面板打不开？面板路径是随机生成的，部署日志里会打印。

优选结果全是 -1？检查域名与 WS 路径是否和客户端一致，端口是否为 443 等 TLS 端口。

提示「版本相同已跳过」？说明线上已是最新版本，无需重新部署；需要强制更新就勾选「强制重新部署」。
