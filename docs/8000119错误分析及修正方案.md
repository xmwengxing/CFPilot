2. **项目级风控标记（Taint Lock）**：一旦某个 Pages 项目在部署或运行期间触发 `8000119`，**该项目名称/实例本身会被标记为受限状态**。即便后续把代码改成一行简单的 `Hello World`，在原项目上二次部署依然会百分百报错 `8000119`。

### 二、 修正与重构方案

要彻底解决 `8000119` 报错，需要从**项目环境重置**、**控制面与数据面物理分离**、**敏感特征脱敏**三个步骤入手：

#### 第一步：废弃已触发 `8000119` 的原 Pages 项目

由于原 Pages 项目已被风控标记锁定，修改代码后**不要在原项目上重新上传部署**。请直接在 Cloudflare 控制台删除原 Pages 项目，换一个全新的、不带 `cfpilot` / `proxy` / `vless` / `edgetunnel` 等字样的普通名称（例如 `blog-assets-sync`、`doc-viewer-web` 等）新建项目。

#### 第二步：真正做到“控制面”与“纯数据面”分离（核心最优选）

如果你的架构本来就是“控制面 + 数据面”，那么部署在数据面节点上的代码**绝不应该包含面板 HTML、订阅生成、优选拉取、规则转换和测速探针**。
建议将 `cfpilot-worker.js` 拆解瘦身，**删掉 70% 的非数据面代码**，仅保留纯粹的转发逻辑：

1. **彻底移除以下模块**：
* 删除 `Hr`（路由规则 Gzip）和 `Rn`（面板 HTML Gzip）以及对应的 `rn()`、`Tn()` 函数。


* 删除 `go()`（Clash 生成）、`yo()`（Sing-box 生成）、`bo()`（Base64 订阅生成）、`Uo()`（`/sub` 路由）、`zr()`/`Xr()`（规则解析）。


* 删除 `ke()`、`ro()`、`lo()`、`co()`（远程 CSV/API 优选拉取）以及 `pe`（21 个公开优选域名）、`on`/`Te`（CF 官方 IP 段）。


* 删除 `Ie()`（`/__edge_probe` 测速流接口）和 `/__diag`、`/region`、`/api/v1/*` 接口。




2. **精简后的数据面只做什么？**
* 只接收 WebSocket 升级请求（`Ge`）和 POST 流请求（`Xt`），认证参数（UUID / 密码哈希 / 转发路径 / ProxyIP）直接通过 **环境变量（`env`）** 传入，或者由独立控制面写入绑定的 KV 中读取。





#### 第三步：如果必须保留完整功能，需进行的源码级脱敏改造

如果业务上必须单文件运行，则必须对源码中的静态特征做以下四项清洗：

**1. 清除所有硬编码黑名单域名与标识**

* **清空 `Ke` 和 `hr` 数组**：将 `*.cmliussss.net` 从源码中彻底删除，改为通过环境变量 `RELAY_POOL` 或 KV 动态下发反代地址。


* **清空 `pe` 数组**：删除源码中的 `cf.090227.xyz` 等 21 个域名，依靠 KV 中的 `POOL_DOMAIN_LIBRARY` 动态存储。


* **删除 `@edgetunnel**`：在 `Wo` 和 `We` 函数中删掉 `r==="@edgetunnel"` 判断（或换成你自定义的随机字符串如 `"@my_custom_tag"`）。


* **修改 User-Agent**：将 `CFPilot/1.1 (+[https://github.com/xmwengxing/CFPilot](https://github.com/xmwengxing/CFPilot))` 替换为通用浏览器 UA（如 `"Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36"`）。



**2. 绕过 `cloudflare:sockets` 的 AST 静态常量折叠**
不要使用 `"cloudflare" + ":sockets"` 这种字面量相加，改为运行时动态解码且利用函数传参阻断 AST 追踪：

```javascript
// 使用异或或字节偏移在运行时还原模块名

  return String.fromCharCode(...arr.map(b => b ^ key));
}

    const loader = new Function("p", "return import(p)");

```

**3. 消除协议名、客户端名与敏感响应头的明文字符串**
构建一个轻量级的字符串解码字典（例如将所有敏感词放入一个经 XOR 异或处理的 `Uint8Array` 字典中，运行时初始化到内存数组），替换以下所有明文：

* 替换所有 `"vless"`、`"trojan"`、`"xhttp"`、`"socks5"`、`"clash"`、`"mihomo"`、`"singbox"`、`"shadowrocket"`、`"v2ray"` 等字符串。


* 替换默认路径：将 `T` 对象中的 `wsPath: "/vless"`、`trojanPath: "/trojan"`、`xhttpPath: "/xhttp"`、`en = "/cfpilot"` 改为无意义的普通 Web 路径（如 `"/api/ws/v1"`、`"/api/ws/v2"`、`"/api/stream"`、`"/admin-portal"`）。


* 替换报错信息：将 `"VLESS 头解析失败"`、`"SOCKS5 握手失败"` 等中文报错全部替换为通用的 HTTP 状态码描述（如 `"Bad Request: 0x01"`、`"Upstream Error: 0x02"`）。



**4. 对内置 Gzip 载荷（`Hr` 和 `Rn`）增加一层 XOR 流混淆**
不要直接将标准 Gzip 的 Base64（以 `H4sIAAAAAAA` 开头，这是标准的 Gzip Magic Header Base64 特征，扫描器见 `H4sI` 就会自动走 Gzip 解压检查）硬编码在代码里：

* 在打包构建阶段，先将 Gzip 后的 `Uint8Array` 每个字节与一个随机密钥（如 `(i * 31 + 0xA5) & 0xFF`）进行异或，再转为 Base64 存入代码。


* 在 `rn()` 和 `Tn()` 读取时，先 `atob` 还原为 `Uint8Array`，执行反向异或解密出真正的 Gzip 字节流后，再送入 `DecompressionStream("gzip")`，即可彻底阻断扫描器对静态 HTML 面板和分流规则的自动解压嗅探。
